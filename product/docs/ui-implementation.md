# PIXEL MIX 客户端实现与验证

日期：2026-09-21。生产项目位置：`product/apps/client`。

## 已实现

- React 19 + TypeScript + Vite + Tauri 2 IPC。原生模式通过 `catalog` 读取 Rust 校验、导入 SQLite 的目录；浏览器明确显示“UI 测试模式”，从未改动的种子副本读取资料，使用独立 `pixel-mix.ui-test.v1` localStorage 键。浏览器模式不伪装原生数据库、订单或规则生成成功。
- 七个可操作区域：当前酒谱、配方抽屉、调制引擎、票据/本机草稿、五味、独立七维、Canvas ASCII 酒杯与评价。暗色像素网格参考用户提供的两张草图；视觉对齐未验收，不宣称三张完整 UI 参考已还原。TIMER_LOGO 来自用户提供文件，字体仅引用系统字体，未捆绑环境中的字体文件。
- 70 份来源酒谱实际由 60 份 IBA 参考网页记录和 10 份用户笔记组成。UI 按 `source.kind` 分别标注，用户笔记无外部 URL，不伪造 IBA 链接。支持中文、英文、原料、家族检索。
- 目标、当前酒谱和预测分别保存。切换匹配/随机候选不修改目标；显式“载入经典先验”一次载入 5+7 维，支持撤销。先验始终显示为未验证；热量和 ABV 保持资料不足。
- 五味使用整数基点，原生调用 Rust `taste_adjust`。浏览器测试实现用稳定最大余数算法，并与原始 Python 生成的 2000 个共同案例对照。Range DOM 使用 `step=1`，避免 `3846` 基点被 HTML 控件静默舍入为 `3850`。手势起点固定；拖动默认 50 基点，Shift 为 10；键盘 Home/End/方向键、悬停滚轮、手机加减按钮、锁定和 pointercancel 恢复均已实现。
- 七维独立 0–10，以 0.1 分步进，不归一。修改在内存，手势结束后延迟保存；撤销记录手势起点。目标持久化序列化写入，避免并发覆盖。
- 配方抽屉共享悬停区、140/180ms 开关延迟、点击固定、Esc 关闭、份数显示、复制含来源和原始单位。窄屏为底部 Sheet。多份标注分批制作，未知数量、dash/splash 等不自动换算。
- 八种 ASCII 杯型移植原参考，Canvas 仅数据/大小改变时重绘，稳定图案，没有空闲动画循环。热点、键盘焦点和点击均有可达入口。图形是混合酒体示意，不映射五味比例为液体层。系统原创酒语明确标注。
- 类型库存过滤与原料排除在匹配、候选和随机之前应用。默认库存为空，未伪造可制作状态。SKU 未核对时显示“类型库存齐备 · SKU 待核对”；不能由此变为客人菜单。
- 收藏、真实评价、目标、设置、原料类型清单和本机草稿经原生 `ui_state_set` 保存到 SQLite。评价需昵称和“已真实品尝、同意本机保存”确认，保存真实 `recipe_revision_id`、时间、分数、说明和完整酒谱快照。无评价时显示“暂无实饮评价”。
- 本机草稿固定目标和酒谱快照，明确未提交、未扣票。真实主机域管理由单独 `HostPanel` 接 `host_call`；客人配对/票据与主机命令边界以主机测试报告为准。顶部票据区提供真实会话入口，跳转主机/客人面板；状态以会话面板实际回执为准，不硬编码未配对或成功。
- 规则试调面板 `TrialPanel` 接 `generate_trial`；15 个原料 ID 与 Rust 当前白名单对应。实际 SKU 品牌、ABV、体积、食品级与过敏原确认需填写；新增 ABV/体积初始为空，不用假定 0 冒充标签值。模型开关默认关闭；试调保留输入快照、原始验证结果与回退原因，不自动加入菜单。
- 可选模型管理由 `ModelPanel` 接真实受控启动、状态和停止 IPC。不会下载模型。
- 设置提供文字缩放、减少动态效果、库存/排除、规则试调、主机、模型、本机草稿、一致性备份/恢复与本机诊断。备份范围明确为个人目录/偏好，不包含主机订单、账户或身份。恢复前刷新并备份当前个人资料，暂停旧 UI 的延迟写入，恢复成功重载；失败恢复保存功能。
- 所有模态窗有焦点锁定、Esc 关闭和关闭后的焦点返回。页面提供全局载入错误边界和真实保存错误反馈。

## 实际验证命令与结果

在仓库根目录执行（Windows PowerShell）：

```powershell
. ./product/scripts/enter-build-env.ps1
pnpm --dir product/apps/client install
pnpm --dir product/apps/client test
pnpm --dir product/apps/client build
node product/tests/e2e/browser-smoke.cjs
```

- 初次 install 由 pnpm 阻止未批准的 esbuild 构建脚本，退出 1；新增 `pnpm-workspace.yaml` 仅批准 `esbuild` 后安装通过。没有允许所有依赖执行脚本。
- 首次领域测试 10/11 通过。失败断言错误地假定全部 70 款都有 IBA URL；检查实际数据确认 10 份用户笔记后修正 UI 来源标注、类型和测试。没有为通过测试补造 URL。
- 加入 JSON 黄金数据测试后首次 `tsc` 报固定元组与 JSON `number[]` 断言不兼容；测试数据边界使用显式 `unknown` 桥接，并由运行时守恒/目录测试验证后，构建通过。
- 原生初测发现 HTML Range step=10 导致非十倍数基点的 DOM 舍入；改 step=1，步长放到真实交互处理器。浏览器 E2E 校验 `3846` 初值保持精确。
- 最后运行：Vitest 11/11 通过，包括 2000 案例 Python 对照、100000 次确定性随机守恒、锁、NaN/Infinity/非整数、手势起点稳定、原始来源、过滤、未知量、8 个 ASCII 参考对照。
- 最后运行：TypeScript + Vite 生产构建通过。实际依赖版本保存在 `pnpm-lock.yaml`；不把声明的版本范围当锁定版本。
- 最后运行：隔离 Chrome 浏览器 E2E 15/15 通过，详见 `product/evidence/ui/browser-smoke.json`。覆盖 70 谱、1280布局、键盘/锁/守恒、触点取消、七维撤销、个人笔记来源、收藏跨 reload、抽屉份数和 Esc、评价确认/快照、库存排除、离线草稿、未知 SKU 初值、1920×1080、1280×800 DPR2、390×844。未发生浏览器页面异常。
- 浏览器测试会在隔离上下文内建立明确标识为 `E2E_SYNTHETIC_BROWSER_ONLY` 的合成评价，以验证表单和快照。这不是用户实饮记录，不写入原生数据库；关闭测试上下文即丢弃。

浏览器测试默认使用目标电脑已存在的 Chrome，Playwright 来自 Codex 当前运行时；未下载浏览器。可用 `PLAYWRIGHT_MODULE`、`CHROME_EXECUTABLE` 和 `PIXEL_UI_URL` 改写路径。测试要求 `127.0.0.1:1420` 上运行 Vite；仅环回监听。原生安装与 SQLite IPC 验证由父任务执行，不归入浏览器测试成功范围。

截图：`product/evidence/ui/browser-1280x800.png`、`browser-1280-full.png`、`browser-1920x1080-dpr1.png`、`browser-1280x800-dpr2.png`、`browser-390x844-dpr1.png`。DPR2 是浏览器高 DPI 仿真，不能替代 Windows 实际显示缩放测试。手机截图同样不能替代 Android/iOS 真机交互验证。

## 仍有边界

- M1 基础功能已实现，但不是任务书全部产品体验的最终验收。灰色先验标记可载入当前配方全部先验；跨多酒谱重叠标记候选弹层尚未实现。
- 配方原始配比只读，尚无完整自定义经典变体编辑器；没有用无效按钮假装存在。
- 七轴可触摸拖拽；手机优先连续堆叠布局，尚未实现五味/七维标签切换形式。触摸控件在浏览器验证，真机未验证。
- 来源、抽屉和预测中的小号辅助文字仍需实际高 DPI、读屏与大字体完整无障碍验收。短屏桌面按区域压缩留白，保留滚动，不能把全部内容强制缩成一屏。
- 菜单与正文目前为中文，原始酒谱保留英文名字；未提供完整国际化、浅色主题、糖浆浓度编辑、器具约束、SKU 批次容量扣减。
- 规则生成结果当前以可审阅的结构化结果展示；没有把未经审核的结果套入经典配方、伪造真实评价或标成可点。
- 真实双设备 LAN 流程、移动端系统权限、Android/iOS 包与模型速度/质量需要分别验证；此客户端页面不证明这些平台已交付。
